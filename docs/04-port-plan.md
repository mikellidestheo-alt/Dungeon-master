# Porting plan: HTML (browser) and Linux (native)

## Legal first
* **OpenKeeper is GPL-3.0-or-later.** If you copy or closely translate its code (even to TypeScript) your result is a derivative
  work and must also be GPL-3 with source available. Writing your own implementation from the *behaviour and data layouts* documented
  here is a clean-room-ish route, but the safest policy is: license your repo GPL-3 and keep attribution.
* **Dungeon Keeper II's art, sound, models, text and level files are EA's.** Don't commit or host them. Two legal designs:
  1. *Bring-your-own-assets*: the page lets the user select their own DK2 install folder (File System Access API / `<input webkitdirectory>`), parses WAD/KWD in the browser or a one-off converter, and keeps the result in IndexedDB.
  2. *Standalone*: your own art/sounds and your own JSON tables that follow the shapes in `02-file-formats.md`.
* The prototype in `web/` uses only procedurally drawn graphics + original numbers, so it is safe to publish.

## Recommended stack

| Goal | Pick | Why |
|---|---|---|
| **HTML** | TypeScript + Vite, sim in a Web Worker, renderer on Canvas2D first, then **three.js** (or Babylon) for the 3D view | JME → three.js is the closest scene-graph analogue; keep sim renderer-free like OpenKeeper does |
| ECS | `bitecs` or hand-rolled Map<componentName, Map<entityId,data>> | Zay-ES entity-sets ≈ cached queries |
| Pathfinding | write A\* yourself (~60 lines, see prototype) or `pathfinding` npm | graph is just a grid with per-creature cost fn |
| Steering | simple waypoint follower first; gdx-ai-style `seek/arrive/separation` later | OpenKeeper separation radius 0.25 tile |
| UI | DOM + CSS over a canvas | replaces Nifty GUI XML |
| Audio | WebAudio; convert SDT (MP2/WAV) offline to OGG | |
| **Linux native** | Same TypeScript in **Tauri/Electron** (cheapest), or a rewrite in **Godot 4** (GDScript/C#) / **Rust + Bevy** (bevy_ecs maps 1:1 to the component list) | Godot gives 3D, UI, audio, export to Linux for free; Bevy is the nearest to the ECS design |

## Milestones (each is shippable)

1. **Grid & terrain** — terrain table JSON, tile `{terrain, owner, hp, gold}`, camera pan/zoom, tag/untag. *(done in prototype)*
2. **Workers** — task board with dig/claim/mine, A\*, imp FSM `IDLE→WORK`, gold carry & treasury. *(done in prototype)*
3. **Rooms** — placement validator, flood-fill room instances, Treasury → Lair → Hatchery → Training; storage controllers.
4. **Creatures** — attributes table, needs (sleep/eat/pay), mood counters, portal spawn, experience.
5. **Combat, doors & traps** — senses, flee/attack decision, melee, unconscious/capture, prison/torture, death/corpses. *(prototype has senses, flee/attack, melee + ranged shots, death, XP, hero parties and waves; unconscious/capture/prison/torture still to do)*
6. **Player powers** *(prototype has the Hand, mana and five spells; research, possession and slap still to do)* — hand pick-up/drop/slap, mana, spell research, possession.
7. **Scripting** — trigger tree interpreter (conditions × actions), action points, objectives, win/lose.
8. **Heroes/AI** — hero gate parties, invasion triggers, rival keeper AI.
9. **BYO-asset loader** — `WadFile`, RefPack decompress, `KwdFile` readers, KMF → glTF converter, texture decoder → PNG. Do this in a Node CLI first (testable against `assets/`), then lift into the page.
10. **3D renderer** *(started: `web/render3d.js` draws the sim with instanced stand-in meshes, no DK2 art, no fog of war or wall-piece selection yet)* — slab meshes from `complete/side/top` art resources, wall-section selection by neighbour mask, lighting from terrain colours, water/lava planes, fog of war texture, minimap.

## Suggested module layout (TypeScript)
```
src/
  data/        terrain.json rooms.json creatures.json variables.json   (or generated by the converter)
  sim/
    world.ts        entity store, tick loop
    components.ts
    map.ts          tiles, damage/heal, ownership, flood fill, listeners
    tasks.ts        TaskManager + Dig/Claim/Fetch/Carry...
    nav.ts          A*, cost fns
    systems/        mood.ts sleep.ts health.ts spawn.ts mana.ts death.ts ...
    rooms/          placement.ts instances.ts storage.ts
    triggers.ts
  render/       canvas2d.ts → three.ts
  ui/           hud.ts panels.ts
  tools/        wad.ts kwd.ts refpack.ts kmf2gltf.ts  (BYO assets)
```
