# Game systems spec (distilled from OpenKeeper)

Each section: **rule** → where it lives in OpenKeeper → how the prototype in `web/` models it.
`[src]` = read in the source. `[dk2]` = general Dungeon Keeper 2 knowledge, not verified in this repo.

## 1. Time
* Logic tick rate is per-level data (`GameLevel.ticksPerSec`), movement/animation run at 60 Hz. `[src]`
* All balance values are **per game second**; apply `rate × dt`. OpenKeeper simplifies to one application per second per task. `[src]`

## 2. Terrain state machine (the core loop)
Every tile has `{terrainId, ownerId, health, gold, selected[player]}`; terrain type supplies flags + `maxHealth`,
`maxHealthTypeTerrainId`, `destroyedTypeTerrainId`. `[src: MapController.damageTile/healTile, TileWork]`

| Action | Applies to | Health change per work-second (×efficiency%) | On reaching 0 / max |
|---|---|---|---|
| Dig rock/earth | SOLID, not OWNABLE, no gold | `DIG_ROCK_HEALTH` −5000 (dwarves ×multiplier) | → `destroyedTypeTerrainId` (path) |
| Mine gold | SOLID with gold | `MINE_GOLD_HEALTH` −300, gold released ∝ health lost | exhausted → path |
| Dig own wall | SOLID + OWNABLE, owner == player | −130 | → path |
| Dig enemy wall | SOLID + OWNABLE, owner != player | −8 | → path |
| Attack enemy floor | OWNABLE, enemy owned, not solid | −140 | becomes neutral |
| Claim floor | unowned path | +825 | owned by claimer at full health |
| Reinforce | SOLID dirt | +50 | → `maxHealthTypeTerrainId` (wall) |
| Repair wall / room | owned | +22 / +20000 | |

Imp efficiency = 80 % when fresh `[src: TileWork.FULL_EFFICIENCY comment]`. Only terrain that is **not** OWNABLE converts at full health;
owned terrain just stops healing (otherwise a claimed path would "heal" into rock). `[src: TileWork.convertsAtFullHealth]`

Only **tagged** tiles are dug: `DigTileTask.isValid` = `tile.isSelected(playerId)`. A dig target is reached from an *accessible neighbour*
(`getAccessibleTargetNextToLocation`), up to **3 imps per task**, priority **10**. `[src]`

> Prototype: terrain table with `solid/ownable/maxHealth/destroyedTo`; tile `hp`; imps apply `rate*eff*dt` per second.

## 3. Task board
See `01-architecture.md §4`. Algorithm to implement:

```
onTileChanged(t): for t and its 4/8 neighbours: re-evaluate tasks for each keeper
  - tagged & solid & reachable-neighbour exists      → DIG(t)
  - own/neutral floor not claimed & adjacent to own  → CLAIM(t)
  - own wall that is damaged                         → REPAIR(t)
  - loose object on own land                         → FETCH(obj)
idle worker: pick best (priority, distance) task it can reach and that has <maxAssignees; assign; path to task.getTarget()
worker.execute(): while adjacent/at target, tick executeTask; on isValid()==false → drop and go idle
```
`Task` objects are **cached per tile per player** (one tile-task per tile) and removed when obsolete (`removeObsoleteTileTasks`).

## 4. Economy `[src: variables; dk2 for names]`
* Gold lives in the tile (seam) → imp carries up to `MAX_GOLD_HELD` → `CarryGoldToTreasury` → Treasury stores ≤ `MAX_GOLD_PER_TREASURY_TILE` (3000) per tile.
  Loose gold piles outside treasury cap at `MAX_GOLD_PILE_OUTSIDE_TREASURY` (2000). Gem seams (IMPENETRABLE + gold) never deplete: pay `GOLD_MINED_FROM_GEMS` per collapse.
* Payday every `PAY_DAY_FREQUENCY_SECONDS` (600; first after `TIME_BEFORE_FIRST_PAY_DAY_SECONDS`); each creature has a `pay` attribute; unpaid → `angerNoPay`. `[src var names, dk2 behaviour]`
* Mana: generated by territory + prayer (`manaGenPrayer`), `ManaCalculatorLogic`; excess decays at `EXCESS_MANA_DECREASE_RATE_PER_SECOND` (5). `[src]`
* Imps: free imp spawn when below `MINIMUM_IMP_THRESHOLD` (4) every `TIME_BEFORE_FREE_IMP_GENERATED_SECONDS` (5). `[src var names]`

## 5. Creature needs & mood
* Each creature has `timeAwake`/`timeSleep`, `hungerRate`/`hungerFill`; sleeps when health < `CREATURE_SLEEPS_WHEN_BELOW_PERCENT_HEALTH` (50) or tired; needs a **Lair** (`room id 2`) bed object. `[src]`
* Mood is a set of **reason counters** (`REASON_NO_LAIR`, `REASON_OTHER`, no-food, no-pay, no-work, slap, in-hand…). Each has a per-creature anger value; state = normal / unhappy / angry by thresholds (`unhappyThreshold`). Lair gives −550 anger/s and +100 hp/s. `[src: CreatureMoodSystem]`
* Hunger → `GoToEat` finds a Hatchery chicken; retry every `TIME_BETWEEN_REATTEMPTING_HUNGER_SECONDS` (4). Sleep retry 4 s. `[src var names]`
* Experience: `expPerSecond`, extra `expPerSecondTraining` in Training Room; levels at `expForNextLevel`. `[src: Attributes]`
* Slap: `SlapSystem` – damage `slapDamage`, anger `angerSlap`, grants brief fearless (`slapFearlessDuration`) and force `FORCE_APPLIED_TO_SLAPPED_CREATURE` 1024. `[src]`

## 6. Rooms
* A **room instance** = connected set of tiles of one room terrain owned by one player (`updateRooms(coordinates)` recomputes via flood fill).
* Placement validity (`RoomPlacementValidator`): terrain flags (`PLACEABLE_ON_LAND/WATER/LAVA`), owned, empty of objects, enough gold. `[src]`
* Room *function* is expressed by what the instance stores (`ObjectType` + `room/storage/*Control`): gold / lairs / food / prisoners / torturees / trainees / researchers / spellbooks.
* Shape determines art, not rules: 1×1 normal, quad 2×2, 3×3, 5×5 rotated, double-quad, centre-pool. `[src]`
* Room health: attackable (`ATTACK_ROOM_HEALTH`), convertible by enemy (`CONVERT_ROOM_HEALTH`), repairable.
* Rooms in DK2 `[dk2]`: Dungeon Heart, Portal, Treasury, Lair, Hatchery, Training Room, Library, Workshop, Guard Room, Barracks, Prison, Torture Chamber, Temple, Graveyard, Casino, Combat Pit, Bridge (wooden id 8 `[src]`/stone).

## 7. Combat `[partly src]` — prototype: `fightBrain`, `Hero`, `spawnWave` in `web/index.html`
* Senses (`distanceCanSee`/`Hear`), `Threat`, `fear`; `shouldFleeOrAttack` first in IDLE. `FightStyle` (blitzer/blocker/flanker/support) chooses engagement. Melee: `CreatureMeleeAttack` w/ `MELEE_DAMAGE`, `MELEE_RECHARGE_TIME_SECONDS`.
* `HealthSystem` applies `Damage` components to `Health`, regenerates on own land (`OWN_LAND_HEALTH_INCREASE_PER_SECOND`), triggers `Death`/`Unconscious`.
* Unconscious creatures → imps create `Rescue` (own) or `Capture` (enemy) tasks → carried to Lair / Prison.
* Dead → `Death` + corpse (`DEAD_BODY_DIES_AFTER_SECONDS` 60), `CAN_BE_RESURECTED`, vampire needs `DECOMPOSE_VALUE_NEEDED_FOR_VAMPIRE` 1000.
* Prison / torture: `PRISON_MODIFY_CREATURE_HEALTH_PER_SECOND` −3, `tortureTimeToConvert`, `tortureMoodChange`.

Prototype doors/traps (`placeThings`, `fireTrap`, `updateTraps` in `web/game.js`): doors block invaders until smashed, traps are hidden, charge-limited and re-armed by imps for gold; OpenKeeper's versions are `DoorsController`/`TrapsController` with `DoorComponent`/`TrapComponent`, manufactured at the Workshop.

Prototype spells (`SPELLS`, `castSpell`, `updateMana` in `web/game.js`) follow the `KeeperSpellCastValidator` pattern: mana cost + cooldown + valid target before anything fires. Not modelled: researching spells in the Library, Temple prayer mana, possession, slap.

Prototype knock-out/prison/torture (`knockOut`, `dropOff`, `updateJail`, `release` in `web/game.js`) follows OpenKeeper's `Unconscious` component and `RescueCreatureTask` / `CaptureEnemyCreatureTask` / `CarryEnemyCreatureToPrison`. Not modelled: jailbreaks by hero parties, torturers (creatures with the TORTURE job), per-creature `tortureTimeToConvert`, the Graveyard, and prisoners being fed.

Prototype research (`RESEARCH`, `addResearch`, Library desks and the `research` creature state in `web/game.js`) follows OpenKeeper's `ResearchableEntity` states and `task/creature/Research`: study at a desk, `researchPerSecond` points per creature. Not modelled: spell/trap/room research *prerequisites*, research stolen by enemies, Workshop crates, and the Temple.

Prototype hatchery/temple (`Chicken`, `updateHatchery`, the `eat`/`pray` creature states in `web/game.js`): chickens hatch per tile, hungry creatures run `GoToEat` and feed `REASON_NO_FOOD`, temple prayer converts `manaGenPrayer` into mana. Not modelled: creatures dying of hunger, chickens as a spell target, the Temple's sacrifice mechanic, and heroes attacking chickens.

Arrivals in the prototype (`NEEDS`, `pickKind`, the Monsters tab's *Who will come* in `web/game.js`): my own rule, not OpenKeeper's. DK2 gates creature kinds by the rooms you own (its level scripts list which creatures can be attracted); the prototype keeps that spirit with a small table of room and tile count per kind and a deterministic weighted draw over the kinds you qualify for.

Levels in the prototype (`XP_FOR_LEVEL`, `gainXp`, the `train` creature state, the Training Room): DK2 has a Training Room where creatures gain experience and `CreatureExperienceSystem` levels them up to 10; the prototype keeps levels 1-10 and the room but the numbers (XP table, 20 s sessions at 15 gold, x1.11 stats, +8% wages a level) are my own tuning, checked by `tools/test_training.js`.

Capacity in the prototype (`armyLimit`, the larder in `updateHatchery`): in DK2 the Portal's supply stops at the level's creature cap and creatures leave when they have no lair or food; the prototype turns both into one visible rule, min(Portal limit, Lair tiles, 3 + 4 per Hatchery tile). The numbers are my own tuning.

Creature tricks in the prototype (`ambush`, `cleave`, `armor`, `heals`, `torturer`, `flying` on the `KINDS` entries in `web/game.js`) are loosely inspired by DK2's creature specials (`Creature.SpecialAbility`, `JobType.TORTURE`); the numbers are my own tuning, not OpenKeeper's.

Hero counters in the prototype (`disarms`, `flying`, `stunImmune`, `gasImmune`, `armor`, `doorBreaker` on the `HEROES` entries in `web/game.js`, and the scripted `WAVE_PLAN`) are my own design to make traps, doors and spells matter in different ways; they are not OpenKeeper behaviour.

## 8. Player verbs (the "hand" & spells) `[src: GameWorldController, PlayerState, KeeperSpellCastValidator]`
Tag/untag dig · build/sell room · place door/trap · pick up creature/object (`InHand`, `Placeable`) · drop · slap · cast keeper spell (mana cost, research state `UNAVAILABLE/RESEARCHABLE/AVAILABLE`) · possess creature (`PossessedSystem`, mana per second).
Research states per item type `ROOM, DOOR, TRAP, SPELL, CREATURE`.

## 9. Heroes & AI keepers
* `CreatureSpawnSystem` / `CreatureGenerator` spawn from portals and hero gates; `Party` (leader + followers → `FollowTarget`). Triggers script invasions.
* AI keepers: `AI.java` (937 lines) parses the AI parameter blocks from level data (build order, aggression). *(Parser read, runtime AI keeper behaviour not found as a separate system — AI keepers appear to be driven by the same creature/task code with different `Keeper.isAi()`; treat as an open question.)*

## 10. Fog of war & minimap
CPU grid of explored flags per player (`game/fogofwar`, `view/fogofwar`), `TerrainFlag.REVEAL_THROUGH_FOG_OF_WAR`, `ALWAYS_EXPLORED`, `UNEXPLORE_IF_DUG_BY_ANOTHER_PLAYER`; creatures reveal radius `perceptionRange`.
